# Git #2. GitHub и Pages — шпаргалка

## GitHub (remote)
- Копия истории в облаке.
- Репозиторий для команды и портфолио.
- Git — программа, GitHub — сайт.

## Связать (remote add)
- Создать пустой репозиторий на GitHub.
- `git remote add origin URL`.
- `git remote -v` — проверить.

## Отправить (push)
- `git push -u origin main` — первый раз.
- Дальше — `git push`.
- `[ahead 1]` — пора push.

## Забрать (pull · clone)
- `git pull` — новые коммиты с GitHub.
- `git clone URL` — проект целиком.
- `[behind 1]` — пора pull.

## Pages (публикация)
- Settings → Pages → main / root.
- Адрес: логин.github.io/репозиторий/.
- Главная — index.html.

## Правило (workflow)
- Перед работой — pull.
- После коммита — push.
- Ошибку читаем: там написано, что делать.

## Исключения и ловушки
1. Репозиторий для существующей истории создаём пустым, без README.
2. Пароль аккаунта в терминале не работает — вход через браузер или токен.
3. origin — только имя; адрес смотрим `git remote -v`.
4. «rejected (fetch first)» — на GitHub новее: сначала pull.
5. clone создаёт новую папку — не забудьте cd в неё.
6. Pages ищет index.html в корне.
7. На Pages регистр в именах файлов важен.
8. Сайт обновляется через минуту после push, не сразу.
9. Публичный репозиторий видят все — никаких паролей в файлах.
10. `-u` нужен один раз: дальше просто push и pull.

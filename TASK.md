Публикуем сайт барбершопа на GitHub Pages и ведём
историю через GitHub. Терминал — в папке homework.
Вместо <логин> — ваш логин GitHub (без угловых скобок).
«Как:» — заготовка: вместо ___ впишите своё.
После каждой команды сверяйте ответ по «Проверьте:».
Шпаргалка — SUMMARY.md рядом.

── ШАГ 1 · ЛОКАЛЬНАЯ ИСТОРИЯ ──
Что: init, .gitignore со строкой SUMMARY.md
     (шпаргалка — не часть сайта), add .,
     commit «Сайт барбершопа». Короткий статус пуст.
Зачем: на GitHub уйдёт только сайт, без шпаргалки.
Как: git init
     echo ___ > .gitignore
     git add .
     git commit -m "Сайт барбершопа"
     git status --short
Проверьте: git status --short после коммита ничего не
           печатает — всё сохранено в истории.

── ШАГ 2 · README СО ССЫЛКОЙ ──
Что: README.md из двух строк:
     # Барбершоп Усы
     Сайт: https://<логин>.github.io/barbershop/
     commit «README со ссылкой на сайт». История.
Зачем: README — первое, что видят на странице
       репозитория: что за проект и где сайт.
Как: git add README.md
     git commit -m "___"
     git log --format=%s
Проверьте: в истории 2 коммита, новый сверху:
           README со ссылкой на сайт
           Сайт барбершопа

── ШАГ 3 · НА GITHUB ──
Что: пустой репозиторий barbershop, remote add origin,
     push -u origin main. Список связей и состояние.
Зачем: копия истории в облаке — и источник для Pages.
Как: git remote add origin https://github.com/<логин>/barbershop.git
     git ___ -u origin main
     git remote
     git status -sb
Проверьте: git remote печатает origin, а git status -sb —
           ## main...origin/main (у вас и на GitHub одно и
           то же). Файлы видны на странице репозитория.

── ШАГ 4 · PAGES ──
Что: Settings → Pages → Deploy from a branch → main,
     / (root) → Save. Откройте ссылку из README.
Зачем: сайт по ссылке — его можно показать кому угодно.
Итог: сайт открывается по ссылке из README.

── ШАГ 5 · ИСПРАВЛЕНИЕ НА САЙТЕ GITHUB ──
Что: на GitHub отредактируйте index.html: цену
     «600 сом» замените на «700 сом» → Commit changes.
     У себя: заберите коммит, история сообщений.
Зачем: правка на GitHub — как чужой коммит. Без pull
       у вас её нет.
Как: git ___
     git log --format=%s
Проверьте: после pull в истории сверху коммит с GitHub:
           Update index.html
           README со ссылкой на сайт
           Сайт барбершопа

── ШАГ 6 · ПРАВКА ОТСЮДА ──
Что: в style.css цвет h1 — #c2531d. add, commit
     «Оранжевый заголовок», push. Состояние ветки.
     Через минуту сайт обновится сам.
Зачем: каждый push обновляет сайт — без загрузки
       файлов вручную.
Как: git add style.css
     git commit -m "___"
     git ___
     git status -sb
Проверьте: git status -sb печатает ## main...origin/main.
           Через минуту на сайте заголовок оранжевый.
